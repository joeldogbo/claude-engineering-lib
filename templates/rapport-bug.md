# Gabarit de rapport de bug

```markdown
## Comportement observé

Ce qui se passe réellement, précisément (message d'erreur exact, capture si pertinent).

## Comportement attendu

Ce qui devrait se passer à la place.

## Étapes de reproduction

1. Étape 1
2. Étape 2
3. Étape 3

## Environnement

- Version de l'application / commit
- OS, navigateur, version du runtime (si pertinent)
- Données/configuration spécifiques nécessaires pour reproduire

## Fréquence

Systématique / intermittente (préciser les conditions si intermittente).

## Impact

Sévérité (bloquant / majeur / mineur), utilisateurs concernés, contournement possible existant.

## Cause probable (si connue)

Hypothèse ou fichier/ligne suspecté.
```

## Règles d'usage

- Toujours inclure des étapes de reproduction précises — un bug qu'on ne peut pas reproduire est très coûteux à corriger durablement (voir skill `debugging-methodology`).
- Ne pas mélanger plusieurs bugs indépendants dans un seul rapport.
